## 第 2 步：动态界域加载与卸载
状态：已完成

已交付：

- `common/realm/ThreeThousandRealmManager.java`：从存档的 `data/ninecun_lingtai/three_thousand_realms.json` 加载元数据，按持久化 ID、展示名和独立种子动态构造 `ServerLevel`，并注册到服务端维度表。
- 动态加载时复用主世界的维度类型与生成器，调用 `markWorldsDirty()` 并发出 `LevelEvent.Load`，使服务端将界域作为正常加载的维度处理。
- `common/realm/ThreeThousandRealmSeedContext.java` 与 `mixin/common/realm/ServerLevelRealmSeedMixin.java`：在构造期隔离界域种子，保证 `ServerLevel#getSeed()`、随机状态和 `StructureCheck` 使用该界域的独立种子。
- `common/event/ThreeThousandRealmEventHandler.java`：在服务端启动前初始化管理器，在服务端 END tick 检查空闲界域，在服务器停止后清理运行时管理器。
- 空界连续达到 `threeThousandRealms.unloadDelayTicks`，且没有玩家和强制加载区块时，发出 `LevelEvent.Unload`、保存、从服务端维度表移除并关闭 `ServerLevel`。
- `META-INF/accesstransformer.cfg`：开放 `MinecraftServer.storageSource`，供运行时创建 `ServerLevel` 使用。

验证：

- 执行 `.\gradlew.bat test --rerun-tasks`，全部测试通过。
- 执行 `.\gradlew.bat build`，构建成功。
- `git diff --check` 通过，无空白错误。
- 检查 `run/logs/latest.log`，未发现本模组的 `MixinApply`、`InvalidInjection` 或注入失败。

运行时限制：

- 当前 `run/mods` 含有仅客户端模组，专用服务器启动会被 BetterGrassify、Oculus 和 Inventory Tabs 的客户端类加载错误阻断；因此动态创建和卸载的完整专服回归需在第 5 步移除这些模组后执行。
