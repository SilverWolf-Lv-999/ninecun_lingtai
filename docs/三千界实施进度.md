## 第 2 步：数据生成维度定义、延迟加载与卸载
状态：已完成（已修正原运行时复制 Stem 的错误实现）

已交付：

- `common/realm/ThreeThousandRealmDataPackGenerator.java`：为每个界域生成世界本地数据包定义，路径为 `world/datapacks/ninecun_lingtai_realms/data/ninecun_lingtai/dimension/<realm-id>.json`。该 JSON 使用原版 `LevelStem.CODEC` 解码，不再从主世界复制运行时 Stem。
- `common/event/ThreeThousandRealmEventHandler.java`：`ServerAboutToStartEvent` 加载界域元数据并补齐配置数量的界域 JSON；`ServerStartingEvent` 在原版 `createLevels()` 之后注册这些既有定义的 Stem，但不创建 `ServerLevel`。
- `common/realm/ThreeThousandRealmManager.java`：启动时将界域元数据及每个界域的世界本地数据包 JSON 补齐至配置数量；持久化定义会被动态注册到 `LEVEL_STEM` 注册表，玩家进入或返回界域时才请求加载对应的 `ServerLevel` 实例。
- `mixin/common/realm/MinecraftServerRealmLoaderMixin.java`：在原版 `MinecraftServer#createLevels()` 枚举 Stem 时排除元数据中管理的界域，覆盖已启用世界数据包和旧 `level.dat` 残留 Stem，避免服务器启动时为全部界域构造 `ServerLevel`；同一 Mixin 只向三千界管理器提供按需加载桥接。它不改写 `MinecraftServer#getLevel()` 或 `levelKeys()`，因此原版和 Forge 指令既不能补全、也不能加载或进入三千界。
- `mixin/common/realm/DimensionArgumentRealmAccessMixin.java`：拦截原版维度参数解析和补全；即使某个三千界已经由玩家路径加载，`/execute in ninecun_lingtai:<realm-id>` 仍按无效维度处理，且不会出现在命令建议中。
- `mixin/common/realm/PlayerListRealmLoadMixin.java`：仅重定向原版 `PlayerList#placeNewPlayer` 内部读取玩家 NBT 目标维度的那次 `MinecraftServer#getLevel()` 调用。目标为已保存三千界时，先按需加载原界域，再让原版继续使用 NBT 中的原维度、坐标和朝向创建玩家；不会改变命令的维度查询或补全路径。
- `mixin/common/realm/MinecraftServerRealmSaveMixin.java` 与 `common/realm/ThreeThousandRealmRegistryUtility.java`：保存 `level.dat` 时从写入的注册表副本移除三千界 Stem。维度 JSON 与 `three_thousand_realms.json` 是持久化来源；下一次启动会重新注册 Stem，而 `createLevels()` 过滤保证这些定义不提前实例化。
- `common/realm/ThreeThousandRealmSeedContext.java` 与 `mixin/common/realm/ServerLevelRealmSeedMixin.java`：在界域构造期将独立种子用于 `WorldOptions#seed()` 的读取路径，覆盖结构检查、末地战斗和未共享的随机序列；`ServerLevel#getSeed()` 同时返回界域种子。
- 空界连续达到 `threeThousandRealms.unloadDelayTicks`，且没有玩家和强制加载区块时，发出 `LevelEvent.Unload`、保存、从服务端维度表移除并关闭 `ServerLevel`。

验证：

- 执行 `.\gradlew.bat test --rerun-tasks`，全部测试通过。
- 执行 `.\gradlew.bat build`，构建成功。
- `git diff --check` 通过，无空白错误。
- `ThreeThousandRealmDataPackGeneratorTest` 覆盖数据包元数据、维度 JSON 路径和结构、重复写入修复、非法命名空间拒绝，以及启动时排除受管理 Stem 的顺序和范围。

运行时验证：

- 执行 `.\gradlew.bat -PserverRegression runServer`，专用服务器成功启动至 `Done (...)!`；启动日志只出现 `minecraft:overworld` 的出生区准备，未创建任何三千界 `ServerLevel` 实例。

## 第 4 步：跨维度返回位置 JSON 持久化
状态：已完成

已交付：

- `common/player/PlayerThreeThousandRealmReturnPosition.java`：定义玩家离开界域时的界域 ID、X/Y/Z 坐标和朝向数据，并拒绝非有限数值。
- `common/player/PlayerThreeThousandRealmReturnState.java`：以 `formatVersion: 1` 将玩家 UUID 与返回位置持久化到 `world/data/ninecun_lingtai/three_thousand_realm_player_returns.json`；使用 UTF-8、临时文件原子替换写入，坏条目会单独忽略。
- `common/realm/ThreeThousandRealmManager.java`：离开已管理界域前写入当前位置；当外部维度的回程目标为主世界且存在记录时，动态加载原界域并使用保存的坐标和朝向传送。成功回归后删除记录；不存在的界域记录会丢弃并继续原主世界传送。
- `mixin/common/realm/ServerPlayerRealmReturnMixin.java`：拦截 Forge 的 `ServerPlayer#changeDimension(ServerLevel, ITeleporter)`。从界域离开到任意非界域时保存位置；回到主世界时改为返回保存的界域位置。返回位置持久化失败会取消本次离开，避免玩家失去可恢复的位置。
- `ninecun_lingtai.mixins.json`：注册服务端通用返回位置 Mixin。由于目标方法为 Forge 新增且运行时名称保持 `changeDimension`，该注入明确使用 `remap = false`。

验证：

- 执行 `.\gradlew.bat test --rerun-tasks`，全部测试通过。
- 执行 `.\gradlew.bat build`，打包和重混淆成功。
- 使用 Forge 47.4.22 的运行时 `srg.jar` 核对目标方法描述符与实际方法名；`git diff --check` 通过。

运行时限制：
