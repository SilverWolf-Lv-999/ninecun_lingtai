# 功法数据包格式

功法使用服务端数据包注册。文件放在：

```text
data/<命名空间>/techniques/<路径>.json
```

例如 `data/example/techniques/sword/azure_sword.json` 会注册为
`example:sword/azure_sword`。执行 `/reload` 后会重新加载功法。

## 完整示例

```json
{
  "name": "青冥剑诀",
  "description": "以木行生机温养剑气。",
  "content": "这里填写玩家需要阅读、理解的完整功法内容。",
  "cultivation_path": "example:sword_cultivation",
  "breathing": {
    "absorption_multiplier": 1.0
  },
  "compatible_elements": ["wood", "metal"],
  "requirements": {
    "minimum_cultivation": {
      "realm": "qi_refining",
      "layer": 3
    },
    "minimum_soul_strength": 2,
    "required_elements": ["wood"],
    "required_techniques": ["ninecun_lingtai:basic_breathing"]
  },
  "comprehension": {
    "minimum_learning_score": 60,
    "perfect_score_mastery": "ninecun_lingtai:minor_mastery",
    "key_concepts": ["以气御剑", "木气温养经脉"],
    "grading_criteria": ["必须说明运气与出剑的先后顺序"],
    "mastery_levels": [
      {
        "id": "ninecun_lingtai:initial_understanding",
        "minimum_score": 60
      },
      {
        "id": "ninecun_lingtai:minor_mastery",
        "minimum_score": 100
      }
    ]
  },
  "effects": [
    {
      "type": "example:sword_damage",
      "parameters": {
        "multiplier": 1.15
      }
    }
  ]
}
```

## 字段说明

- `name`：必填，功法名称。
- `description`：可选，功法简介。
- `content`：必填，交给玩家阅读、也会提供给 AI 评分的正文。
- `cultivation_path`：可选，自由资源 ID，默认是
  `ninecun_lingtai:spiritual_cultivation`。剑修、枪修、符修等流派不使用写死枚举。
- `breathing`：可选。带有此字段的功法是呼吸法。修炼境界（打坐吸纳灵气）必须依托一门已学会的
  呼吸法，没有呼吸法时打坐不会吸收任何灵气。`absorption_multiplier` 表示呼吸法的强弱，必须为
  正数，默认 `1.0`（基础吐纳诀的水准，最弱的基准）；数值越大，吐纳灵气越快。实际吸收速度还会
  乘以该呼吸法的学习阶段效率：入门 50%、小成 70%、大成 85%、圆满 100%。
- `compatible_elements`：可选，至少有一种相符灵根即可学习。省略表示不限制；混沌灵根始终兼容。
- `requirements`：可选，学习前置条件。
- `comprehension`：必填，AI 理解评分规则。
- `effects`：可选，效果类型和参数。数据包负责选用效果；提供效果行为的模组通过
  `TechniqueEffectApi.register` 注册对应处理器。

### requirements

- `minimum_cultivation`：可选，最低境界。`realm` 可使用
  `qi_refining`、`foundation_establishment`、`golden_core`、`nascent_soul`、
  `spirit_transformation`、`dao_integration`、`void_refinement`、`mahayana`、`immortal`；
  `layer` 为 1 到 9。
- `minimum_soul_strength`：可选，最低魂魄点亮星数，范围 0 到 7，默认 0。
- `required_elements`：可选，列出的灵根元素必须全部具备；混沌灵根自动满足。填
  `["chaos"]` 可以做出只有混沌灵根才能修炼的功法：普通灵根不含混沌元素而无法满足，
  混沌灵根则自动通过（内置的“混沌归元诀”即用此写法）。
- `required_techniques`：可选，必须先学会的功法 ID。

### comprehension

- `minimum_learning_score`：最低学习分数，0 到 100，默认 60。
- `perfect_score_mastery`：100 分时直接进入的层级，默认
  `ninecun_lingtai:minor_mastery`，即“小成”。
- `key_concepts`：关键理解。玩家准确提及这些概念或同义表达时，AI 会显著加分。
- `grading_criteria`：该功法独有的补充评分要求。
- `mastery_levels`：分数到熟练层级的映射。第一项分数必须等于
  `minimum_learning_score`，各分数和层级 ID 不得重复。

## AI 配置

首次启动后编辑 `config/ninecun_lingtai-common.toml`：

```toml
[ai]
provider = "OPENAI"
apiKey = ""
model = ""
```

`provider` 目前只能是 `OPENAI` 或 `DEEPSEEK`。`apiKey` 与 `model` 必须填写为所选
提供方签发的密钥和模型 ID。模型 ID 不写死，以便服务器在模型更新或下线后直接修改配置。
API Key 只由服务端发起评分请求时读取，不会通过模组网络包同步给客户端；仍需妥善保护配置文件。

## 功法玉简与烙印

创造模式的“九寸灵台”栏会提供空玉简，并为每份已加载的功法生成一枚便于测试的成品玉简。
所有玉简都统一显示为“玉简”，共用 `ninecun_lingtai:jade_slip` 物品类型；只有提示文本会显示
其中承载的功法信息。成品玉简通过 NBT 区分功法：

- `ninecun_lingtai:technique_id`：服务端功法资源 ID，是打开与烙印时的权威标识。
- `ninecun_lingtai:technique_name`：物品提示中展示的功法名称。
- `ninecun_lingtai:technique_description`：物品提示中的简介。

功法正文不写入物品 NBT。玩家右键成品玉简时，服务端会按 `technique_id` 查找当前数据包中的
功法，再将正文发给客户端，因此 `/reload` 后阅读到的始终是最新版本。点击阅读界面底部的
“烙印”会把该功法保存到玩家魂魄中；服务端仍会确认玩家在主手或副手持有对应的成品玉简。

玩家右键空玉简时，服务端会发送该玩家已经掌握且当前仍存在的功法列表。可烙印来源包括从成品
玉简烙印到神魂中的功法，以及通过 AI 评分真正学会的功法。玩家选择一门功法后，服务端会再次
确认玩家掌握该功法，并且原本那只手中仍持有空玉简，然后才把功法 ID、名称和简介写入玉简。
