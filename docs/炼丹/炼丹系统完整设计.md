> 版本：v1.1（2026-08-13，已纳入选方、分段投药与三式灵力控火）
> 适用分支：master（net.seraphina 包结构）
> 关联文档：`docs/炼丹.md`（原始设定，本文是其工程化细化）、`docs/五行相生.md`、`docs/一些基础设定.md`、`docs/灵石.md`
> 配套文档：`docs/炼丹/炼丹体系扩展设计.md`（大体系篇：材料/器物/技艺/知识/产出/天地六层，本文为其中"玩法层"的核心机制）

## 一、设计目标与原则

1. **难度合理**：练气期照抄丹方、不做任何操作也能有约 70% 成功率；想炼出高一品的丹，才需要控火、选环境、拼资质。难度随丹方阶数指数上升，与境界成长曲线（`MEDITATION_ABSORPTION_REQUIREMENT_EXPONENT` 的指数模型）保持同一量级。
2. **五要素模型**：一炉丹 = 丹方 × 药材 × 火候 × 人（资质/境界/神识/灵力） × 地（环境五行/灵气浓度）。前两者是准入门槛（是/否），后三者决定成败与品阶（好/坏）。
3. **服务端权威**：所有评分、扣灵力、成丹判定只在服务端进行，客户端只发"意图"包（开始/结束/按住控火），沿用现有 `AlchemyFurnaceActionPacket` 的模式。
4. **数据驱动**：所有新机制参数写进丹方 JSON 与 `CommonConfig`，不写死在代码里。缺省值保证旧丹方行为不变。
5. **不推翻现状**：保留现有 6 槽布局（1 主药 + 2 次药 + 2 辅药 + 1 输出）、打火石点火、`heat` 倒计时、`brewing_duration` 等已实现内容，在其上叠加机制。
6. **无进度提示，收丹自把握**：炼制进度（`refiningTicks`）**永不同步给客户端**（这也是现状代码的既有行为），界面上没有进度条、没有剩余时间。丹是否炼成、何时收丹，靠玩家自己数点火次数、跟火候节奏、闻丹香判断——收丹时机本身就是丹师的本事，是本系统的核心玩法之一。
7. **按丹方复杂度渐进**：分段投药不是境界或六阶专属硬开关，而是丹方可选工序。聚气散保持一次投齐；草还丹、玉髓丹、结金丹依次引入一段投药、升降温配合投药、两段投药，后续内容按复杂度扩展。

## 三、总览：一炉丹的生命周期

```
学习丹方 ──> 选择已学丹方 ──> 装入开局材料 ──> 点火 ──> 起炉
                                                           │ 炼制中：已有材料锁定
                                                           │ 催火 / 收火 / 稳火
                                                           │ 指定阶段开放延后材料槽
                                                           │ 服务端记录火候与投药精度
                                                           │ （只同步槽位事件，不同步进度）
                                                    │
                                           玩家点"收丹" ←—— 时机自己把握
                                                    │
                                    服务端按收丹时机 t = 已炼时长/成丹时长 分支：
                    ┌───────────┬───────────┼───────────────┬───────────┐
                 t < 0.8    0.8 ≤ t < 1.0   1.0 ≤ t ≤ 1.3   1.3 < t ≤ 1.6   t > 1.6
                【炸炉】      【废丹】      【成丹窗口】       【过火】      【焦丹】
              药力中断反噬    出药渣     正常结算(第七节)   品阶额外惩罚   材料化灰
                                        成/败/±品/完美
```

（炼制中 heat 归零仍然直接化灰，与现状一致——火都熄了，谈不上收丹。）

## 四、五要素之"人"：资质、境界、神识

### 4.1 灵根契合度（rootScore）

丹方新增**主属性** `element_profile.primary_element`（金/木/水/火/土/阴阳之一）。玩家灵根元素集合与丹方主属性按 `ElementType.getRelationTo` 取**最优关系**（多灵根取对自己最有利的一条）：

| 关系 | rootScore 系数 | 说明 |
| --- | --- | --- |
| SAME（同属性） | 1.00 | 火灵根炼火属丹，完全契合 |
| GENERATED_BY（灵根生丹属，如木根炼火丹） | 0.92 | 略有损耗但顺势 |
| GENERATES（丹属生灵根，如火根炼土丹） | 0.85 | 可炼，不顺手 |
| NEUTRAL | 0.75 | 无关属性 |
| OVERCOMES / OVERCOME_BY（相克） | 0.60 | 水根炼火丹，强行压药性 |
| 混沌灵根（六系全占） | 0.90（对所有主属性） | 全能但不精，延续"混沌全而不专"的设定 |

最终 `rootScore = 关系系数 × (0.6 + 0.4 × root.quality())`。九寸单火根炼火丹 = 1.0；一寸杂灵根炼相克丹 ≈ 0.39。灵根长度用现有 `SpiritualRoot.quality()`（寸/9），不新增数据。

### 4.2 神识/魂魄（soulScore 与信息精度）

魂魄星数（1-7）扮演两个角色，呼应 `docs/炼丹.md` "炼丹至少需要神识"的设定：

1. **评分项**：`soulScore = 0.55 + 0.45 × soul.quality()`（1 星 0.614，7 星 1.0）。
2. **信息精度（软性难度，不改数值只改 UI）**：
   - 1-2 星：火候条只显示当前温度指针，**不显示目标火候带**（盲炼，靠丹方文字里的"文火/武火"提示自行判断）；
   - 3-4 星：显示目标火候带，但带边界模糊（±40 热度渲染为渐变）；
   - 5-7 星：精确显示目标带 + 阶段切换前 2 秒的预告闪烁。

这样低神识玩家仍然**能**炼丹（保底成功率在），只是难拿高品。

### 4.3 境界（realmScore 与越阶规则）

- 保留 `minimum_refining_realm` 硬门槛。
- 丹方阶数 `tier` 对应境界序号（一阶=练气 ordinal 0，九阶=仙 ordinal 8）。定义境界差 `Δ = 玩家境界 ordinal − (tier − 1)`：

| Δ | realmScore | 说明 |
| --- | --- | --- |
| Δ < 0 | 不允许起炉（现有门槛拦截） | 越阶炼丹直接禁止，避免刷丹 |
| Δ = 0 | 0.85 + 0.15 × (layer / MAXIMUM_LAYER) | 同阶炼丹，层数越高越稳 |
| Δ = 1 | 1.05 | 高一境炼低阶丹，驾轻就熟 |
| Δ ≥ 2 | 1.10（封顶） | 再高也只有 10% 加成，防止大佬无限刷低阶极品丹 |

### 4.4 灵力（消耗，非评分）

灵力不进评分公式（避免"有钱=高品"），只作为**控火的资源成本**，见第六节。扣费使用现有 `PlayerSpiritualEnergyData.consumeEnergyAny`，优先扣与丹方主属性相同/相生的元素池（顺序：SAME → GENERATED_BY → 其余），体现"以火灵力控火最省"的直觉：非契合元素扣费按 1.25 倍折算。

## 五、五要素之"地"：环境五行与灵气浓度

### 5.1 环境评分（envScore）

复用 `ElementEnvironmentManager` 的逐元素倍率（维度 × 群系 × 天气，`docs/五行相生.md` 的既有口径），对丹方主属性元素取倍率 `m`：

```
m = 0            → 禁止起炉，提示"此地灵气死寂，无法引动药性"（如在海底炼火丹、在下界炼水丹）
0 < m < 1        → envScore = 0.55 + 0.45 × m        （受压制，最低 0.55）
1 ≤ m ≤ 2        → envScore = 1.0 + 0.10 × (m − 1)   （浓郁环境最多 +10%）
m > 2            → envScore = 1.10（封顶）
```

设计意图：环境是**锦上添花**而非硬门槛（除了 0 的极端压制），玩家不需要为每一炉丹跑图，但沙漠里炼火丹、雨天炼水丹确实更好。这与打坐吸收共用同一套环境数据，零新增数据源。

### 5.2 灵气浓度对炼制速度的影响

主属性倍率 `m` 同时缩放**实际炼制时长**：`实际时长 = brewing_duration / clamp(m, 0.5, 1.5)`。浓郁环境最多快 33%，压制环境最多慢一倍。速度与品质分开，让"跑图选址"有两种收益但都不粗暴。

### 5.3 环境在 UI 中的呈现

炼丹界面左上角显示丹方主属性图标 + 当前倍率（如"火 ×1.4"），倍率≥1 绿色、<1 红色、=0 深灰并禁用开始按钮。数据通过 `ContainerData` 新增槽同步（定点数 ×100 存 int）。

## 六、火候系统（核心操作玩法）

### 6.1 温度模型与三档火

沿用现有 `heat`（0-600，每 tick 自然 −1），把连续温度切成三档：

| 档位 | 热度区间 | 获得方式 |
| --- | --- | --- |
| 文火 | 1 – 200 | 点火后自然衰减到该区间；或轻度维持 |
| 中火 | 201 – 400 | 点火后中段；或中度维持 |
| 武火 | 401 – 600 | 刚点完火；或高强度维持 |
| 熄火 | 0 | 炼制中归零 → 材料化灰（现状行为保留） |

### 6.2 丹方火候曲线（heat_stages）

丹方新增可选字段 `heat_stages`：按顺序的阶段数组，每段指定目标档位与时长占比。示例（草还丹，温养系）：

```json
"heat_stages": [
  { "band": "medium",  "portion": 0.4 },
  { "band": "gentle",  "portion": 0.6 }
]
```

`portion` 合计必须为 1.0；`band` 取 `gentle / medium / fierce`。**缺省**（旧丹方）视为全程任意档位均正确，即 fireScore 恒为 1.0——保证向后兼容。丹方描述文字（`content`）应与曲线呼应（"先以中火烘去露气……缓缓收火"），神话丹方靠玩家读文字自己领悟，呼应原设定"丹方只说个大概"。

**曲线编排约束**：凡火仍只负责把炉温粗暴拉满，但“催火/收火/稳火”已经提供连续精调，因此曲线可包含升温与降温。复杂曲线仍应按内容阶梯投放：教学丹顺自然衰减，一阶样板只要求一次延后投药，二阶起再引入回升段，避免把所有操作同时压给新手。

### 6.3 玩家控火手段

1. **续火**：打火石再次右键，`heat` 回满 600（现状），代价是打火石耐久——粗放但廉价，只适合武火段。
2. **催火（STOKE）**：长按“催火”，服务端每 tick 稳定升温，默认 `+3 heat/tick`；用于中途升档和抵消自然降温。
3. **收火（VENT）**：长按“收火”，服务端每 tick 主动降温，默认 `−4 heat/tick`；用于快速进入下一低火段。
4. **稳火（MAINTAIN）**：长按“稳火”，把 heat 锁定在当前档位中点（文 100 / 中 300 / 武 500）。

```
控火消耗/秒 = maintainBaseCost × 1.9^(tier − 1) × 档位系数 × 操作系数
档位系数：文火 0.6 / 中火 1.0 / 武火 1.6
操作系数：催火 1.4 / 收火 1.0 / 稳火 1.0（均可配置）
```

扣费优先同属性池，其次生主属性的池，最后可从任意池按 1.25 倍折算。玩家关界面、离炉、死亡、切换维度、灵力不足或区块重载时立即释放控火；控火意图不持久化。打火石仍是“凡火粗调”，三式灵力控火负责精调。

### 6.4 火候评分（fireScore）

服务端逐 tick 判定当前 heat 所在档位是否等于当前阶段目标档位，统计命中 tick 数：

```
fireScore_raw = 命中tick / 总tick     （总tick = 起炉到收丹的全程，含 t>1.0 的养丹段）
容差修正：fireScore = fireScore_raw ^ (1.6 − 0.6 × root.quality())
```

曲线阶段按"实际成丹时长"归一切分；`t > 1.0` 后目标档固定为最后阶段的档位（养丹期继续控火，收得晚不白守，但也稀释不了前面脱靶的账）。

九寸灵根指数 1.0（所得即所见），一寸灵根指数约 1.53（同样 80% 命中率只折算成 71%）——灵根差的修士手感"迟钝"，这是资质影响操作的第二通道（第一通道是 4.1 的直接系数）。

### 6.5 收丹时机与丹香（无进度提示的核心玩法）

**收丹窗口**：设 `t = refiningTicks / 实际成丹时长`，玩家点"收丹"时按 t 分支（见第三节流程图与 7.4 表）。窗口 `[1.0, 1.3]` 内收丹正常结算；早收惩罚重（对齐原设定"停止则炸炉"），晚收先降品再焦丹——两侧都有风险，"守着炉子什么时候开"成为真实的决策。

**玩家的计时锚点**（没有进度条，但把握时机有章法）：
1. **点火次数**：一次点火恰好 600 tick（30 秒），本身就是天然沙漏——"这炉丹要两次半火"是玩家会自己总结的经验语言；
2. **火候曲线节奏**：跟着丹方阶段做操作，做完最后一段就接近成丹；
3. **丹香**：`t = 1.0`（进入成丹窗口）时刻，按魂魄星数判定是否/何时"闻到"——7-5 星必闻且准时；4-3 星 80% 概率闻到、可延迟至多 5% 时长；2-1 星仅 40% 概率闻到。UI 顶部渐入渐出"一缕丹香从炉中飘出"（原设定文案）。**丹香只是感知，不改变结算**——低神识修士炼丹，就得老老实实数火。

超过 `t = 1.0` 后曲线视为停在最后阶段的目标档（养丹期继续控火，不稀释火候得分）。

## 七、结算：成功率与品阶公式

### 7.1 综合评分

```
无 feed_plan：operationScore = fireScore
有 feed_plan：operationScore = fireScore × 0.65 + feedScore × 0.35

score = operationScore × 0.35 + envScore × 0.20
      + rootScore × 0.15 + soulScore × 0.15 + realmScore × 0.15
```

投药分按阶段内距离最佳投入点连续计算：窗口起止边缘约 0.70，最佳点 1.00；超过书面窗口但仍在本阶段可补投，分数继续降至阶段末 0.25；跨阶段未投即漏投。旧丹方直接令工序分等于火候分，因此数值不漂移。工序整体仍沿用原 35% 总权重，火候与投药不会重复放大。

### 7.2 成功率

```
baseSuccess(tier) = 0.95 − 0.05 × (tier − 1)      （一阶 0.95，九阶 0.55，可被丹方 JSON 覆盖）
successRate = clamp(baseSuccess × score, 0.05, 0.98)
```

典型情形（一阶草还丹）：
- 练气三层、三寸单木根、平原白天、完全不控火（旧丹方无曲线时 fireScore=1）：score ≈ 0.35+0.20+0.117+0.10+0.132 ≈ 0.90 → 成功率 ≈ 0.85。**新手无痛**。
- 同上但丹方带曲线且玩家不控火（命中率≈40%）：score ≈ 0.74 → 成功率 ≈ 0.70。**符合"不操作约七成"的目标**。
- 九寸火根、7 星、沙漠、认真控火 95% 命中：score ≈ 1.02 → 成功率 0.95 封顶前 ≈ 0.97 → 0.97。

### 7.3 品阶偏移（rank 结算）

成功后，成丹品阶 = 丹方 rank + Δrank：

| score 区间 | Δrank | 备注 |
| --- | --- | --- |
| < 0.60 | −2 | 勉强成丹，火气驳杂 |
| 0.60 – 0.75 | −1 | |
| 0.75 – 0.90 | 0 | 照方成丹 |
| 0.90 – 1.00 | +1 | |
| ≥ 1.00 且 operationScore_raw ≥ 0.9 | +2，且 20% 概率产量 +1 | "完美"，需环境+资质+工序全部在线 |

rank 越界处理：低于 1 夹到 1；高于 9 进位无效（一阶九品就是该阶天花板，想要更高去炼二阶丹）。成丹 `ItemStack` 写入 NBT `ninecun_lingtai:pill_grade = {Tier, Rank}`，效果结算走现有 `AlchemyGrade.getEffectMultiplier()`（每级 +5%），tooltip 用现有 `getDisplayName()` 上色。**未写 NBT 的存量丹药按丹方原品阶处理**（兼容）。

### 7.4 失败与惩罚分支（按收丹时机 t 与结算掷骰）

| 分支 | 触发 | 后果 |
| --- | --- | --- |
| 化灰 | 炼制中 heat 归零 | 材料清空（现状保留），播放灰烬粒子 |
| 炸炉（早收） | 收丹时 `t < 0.8`——药力中断反噬 | 材料清空 + 以炉心为中心爆炸：强度 `1.0 + 0.5 × tier`（默认不破坏方块，config 可开），周围实体着火 3 秒。落实 `docs/炼丹.md`"停止则炸炉"的原设定 |
| 废丹（早收） | 收丹时 `0.8 ≤ t < 1.0`——将成未成 | 输出槽产出 1 枚 `ninecun_lingtai:dregs_pill`（药渣） |
| 过火（晚收） | 收丹时 `1.3 < t ≤ 1.6` | 正常进入第七节结算，但品阶偏移每超 0.15 追加 −1 |
| 焦丹（晚收） | 收丹时 `t > 1.6`——药力燃尽 | 材料清空，不爆炸，播放焦烟粒子 |
| 迟投 | 延后材料超过 `window_end`、但仍在所属阶段补投 | 投药精度继续下降；本炉失去正品阶偏移与完美加产资格 |
| 漏投/材料篡改 | 延后材料跨阶段仍未投，或收丹时材料不再符合丹方 | 清空本炉材料并固定产出药渣，不进入成功率掷骰 |
| 炸炉（掷骰） | 窗口内收丹但成功率掷骰失败且 score < 0.5 | 同炸炉 |
| 废丹（掷骰） | 窗口内收丹但成功率掷骰失败且 score ≥ 0.5 | 同废丹。药渣可作为低阶丹方的辅药替代品或直接食用回复 1 点饥饿（保留残值，参考修仙模拟器"炼毁的丹药"设计） |

**投料后未点"开始炼制"前**随时可取回材料，不惩罚放错料。

```json
{

  "description": "一阶一品疗伤丹方……",
  "content": "以新采青草为主药，先以文火烘去露气……缓缓收火……",
  "grade": { "tier": 1, "rank": 1 },
  "allowed_realms": ["qi_refining", "foundation_establishment"],
  "minimum_refining_realm": "qi_refining",
  "ingredients": {
    "primary":   { "item": "minecraft:grass", "count": 6 },
    "secondary": [ { "item": "minecraft:fern", "count": 4 },
                   { "item": "minecraft:moss_block", "count": 2 } ],
    "auxiliary": [ { "item": "minecraft:azalea_leaves", "count": 4 },
                   { "item": "minecraft:flowering_azalea_leaves", "count": 4 } ]
  },
  "output_item": "ninecun_lingtai:grass_restoration_pill",
  "output_count": 1,
  "brewing_duration": 500,
  "pill_effect": { "max_health_fraction": 0.10, "flat_healing": 3.0 },

  "element_profile": { "primary_element": "wood" },
  "base_success_rate": 0.95,
  "heat_stages": [
    { "band": "medium", "portion": 0.4 },
    { "band": "gentle", "portion": 0.6 }
  ],
  "feed_plan": [
    {
      "slot": "auxiliary_2",
      "stage": 2,
      "window_start": 0.25,
      "ideal": 0.50,
      "window_end": 0.75
    }
  ],
  "failure": { "dregs_item": "ninecun_lingtai:dregs_pill", "dregs_count": 1 }
}
```

**缺省规则**（旧丹方零改动可用）：
- `element_profile` 缺省 → rootScore / envScore 恒为 1.0（该丹不吃属性）；
- `base_success_rate` 缺省 → 按 `0.95 − 0.05 × (tier − 1)` 表取值；
- `heat_stages` 缺省 → fireScore 恒 1.0；
- `feed_plan` 缺省 → 五味材料仍在开局一次投齐，`operationScore = fireScore`；
- `failure` 缺省 → 失败即化灰，不出药渣。

`feed_plan.slot` 取 `primary / secondary_1 / secondary_2 / auxiliary_1 / auxiliary_2`；`stage` 在 JSON 中从 1 开始；三个时间点均为阶段内 `[0,1]` 归一值并满足 `window_start ≤ ideal ≤ window_end`。同一槽只能出现一次，阶段不得越界，且有投药计划时必须定义火候阶段。其余校验保持不变；解析失败抛 `JsonParseException` 并跳过该丹方。

| 包 | 方向 | 载荷 | 说明 |
| --- | --- | --- | --- |

| `ContainerData` 扩展 | S2C | heat/refining/env + open/missed/fed/late/planned 掩码 + 控火模式 | 只同步当前客观事件。**refiningTicks、火候/投药得分、目标档位一律不同步** |

**目标火候带的客户端本地推算**：客户端在看到 `refining` 翻转为 true 的那一刻起本地计时，按已同步的选定丹方与 `heat_stages` 推算目标档。中途关闭界面再打开，本地计时丢失，目标带显示为“？”；但服务端会恢复选定丹方和投药槽位状态，因此仍可继续完成书面投药动作。

安全边界：选方、槽位物品/数量、投药窗口、控火扣费、评分和成丹全部由服务端重算；客户端状态仅供展示。服务端在玩家关闭菜单、离炉 8 格、死亡、换维度、灵力不足或重载时自动松手。

## 十一、难度基准与平衡表

**各阶基准**（`brewing_duration` 为建议值，写入丹方 JSON；600 tick = 30 秒 = 一次点火的完整燃烧期）：

| 阶 | 对应境界 | 建议时长(tick) | 点火次数(不控火) | 中火维持(灵力/秒) | 不操作成功率* | 认真操作成功率* |
| --- | --- | --- | --- | --- | --- | --- |
| 一 | 练气 | 400–500 (≤25s) | 1 | 0.40 | ~70% | ~95% |
| 二 | 筑基 | 900 (45s) | 2 | 0.76 | ~66% | ~93% |
| 三 | 金丹 | 1200 (60s) | 2 | 1.44 | ~62% | ~91% |
| 四 | 元婴 | 1800 (90s) | 3 | 2.74 | ~57% | ~89% |
| 五 | 化神 | 2400 (2min) | 4 | 5.21 | ~52% | ~86% |
| 六 | 合道 | 3600 (3min) | 6 | 9.90 | ~46% | ~83% |
| 七 | 炼虚 | 4800 (4min) | 8 | 18.8 | ~40% | ~80% |
| 八 | 大乘 | 7200 (6min) | 12 | 35.7 | ~33% | ~76% |
| 九 | 仙 | 9600 (8min) | 16 | 67.9 | ~25% | ~72% |

\* "不操作"= 同阶境界、中位资质、普通环境、带火候曲线的丹方且全程只点火不维持；"认真操作"= 命中 90%+、契合灵根、合适环境。两列均假设玩家在成丹窗口内收丹（靠数点火次数或丹香把握）；收偏了另按 7.4 的时机分支惩罚。高阶丹时长越长、点火次数越多，计时误差越容易累积——**"守炉数火"本身就是高阶丹难度的一部分**（窗口绝对宽度 = 0.3 × 时长，随时长同步放宽，抵消部分累积误差，难而不苛）。高阶丹即使满配也留 ~25% 失败率——顶级丹药就该有炸炉的心跳，废丹药渣与 +5%/级 的品阶收益共同兜底，让失败不至于血本无归。

**一阶时长特意压到 500 以内**：一次点火有 600 tick 火，一阶丹 `t=1.0` 落在 400–500 tick，玩家"点火即起炉、看着火快熄时收丹"恰好落进成丹窗口——第一炉丹不需要任何计时技巧，火本身就是沙漏。若一阶也用 600，`t=1.0` 与 heat 归零重合，收丹窗口会被化灰吃掉。二阶起时长按 600 的倍数编排，玩家开始用"点火次数"计数。

**存量丹方迁移**：`grass_restoration_pill.json` 的 `brewing_duration` 从 200 提到 500，并补 `element_profile`（wood）与上文火候曲线（中 0.4 / 文 0.6）；`minimum_healing` 旧字段解析兼容保留。

## 十二、UI/UX 设计（对齐 docs/炼丹.md）

1. **选方区**：空闲时循环选择服务端同步的已学丹方；选定后延后投药槽立即封印。炼制中选方区锁定，服务端拒绝换方。
2. **槽位状态**：延后槽分“封/投/缺/已投”四态；窗口开启时金色描边，跨阶段漏投转红。只显示事件，不显示窗口百分比或剩余时间。
3. **火候条（右下角）**：
   - 纵向条，从下到上渲染 文火(暗红) / 中火(橙) / 武火(亮黄) 三段色带，指针 = 当前 heat（heat 本来就同步，这是温度不是进度）；
   - 目标档位带按神识等级渲染（见 4.2：不显示/模糊/精确），档位推算完全由客户端本地计时驱动（第九节）；
   - 火候条左侧为“催火 / 收火 / 稳火”三个长按按钮，按住时显示蓝色控火光。
4. **绝不显示的东西（设计原则第 6 条）**：炼制进度条、剩余时间、已炼时长、实时火候分、实时投药分——一律不做。
5. **顶部飘字**：丹香提示（经神识过滤）为渐入渐隐；收丹按钮不做任何时机预警。
6. **环境角标**：左上角主属性图标 + 倍率（第 5.3 节）。
7. **结算反馈**：成丹时输出槽闪光 + 品阶颜色 toast；失败按炸炉、焦丹、漏药分别反馈。

## 十三、实施计划（三个里程碑）

**M1 —— 结算骨架（后端为主，1 个丹方即可验证）**
1. JSON v2 解析（`element_profile`/`base_success_rate`/`heat_stages`/`failure`，全可选）；

1. 丹香/炸炉演出、粒子与音效；
2. 药渣物品与用途；
3. 按第十一节的时长/曲线基准补 2-4 个新丹方（筑基、金丹阶各至少一个）铺进度曲线；
4. 平衡回归：按平衡表跑批量模拟（gameTest 或临时命令 `/ninecun alchemy simulate <recipe> <次数>`）核对成功率。

## 十五、设计取舍备忘（为什么这么设计）

1. **分段投药按丹方复杂度启用**：已证明五槽模型可通过“选方后封槽 + 位掩码恢复”承载时序投料，不再限定六阶。简单丹方不写 `feed_plan`，复杂丹方逐步增加 1–2 次延后投药；第一版拒绝错误材料，不做随机变方。
2. **不做鬼谷八荒式"元素配平加料"**：需要给每种药材标注元素含量表，内容成本极高；保留其精神——用"主属性 × 环境 × 灵根"的三方契合替代。
3. **环境只取主属性单元素倍率**，不做五行全谱评分：全谱会让玩家看不懂"为什么这里炼丹差"；单属性 + UI 角标是可解释的。
4. **成功率下限 5%、上限 98%**：永远有翻车与惊喜，杜绝"100% 流水线"与"0% 劝退"。
5. **灵力只买"稳定"不买"品质"**：品质必须来自操作命中率，灵力维持只是让命中变容易——付费（资源）降低操作门槛，但不能跳过操作。
6. **为什么坚决不做进度条**：这是原始设计意图（现状代码就从不同步 refiningTicks），也是玩法支点——一旦有进度条，"收丹时机"退化为"等读条"，火候曲线退化为 QTE，丹香、数火、神识感知全部失去意义。收丹的紧张感来自不确定，不确定来自信息不完整。工程上以"客户端拿不到就作弊不了"兜底：mod 界面魔改也读不到进度，只能真数火。
