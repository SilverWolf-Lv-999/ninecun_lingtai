## 一、材料层：灵药体系

### 1.1 灵药分阶

灵药与丹方同用 1-9 阶，**丹方的主药阶数即丹方阶数**（一阶丹用一阶主药）。次药允许低一阶，辅药允许低两阶——高阶丹消耗的主要是高阶主药，低阶药材保持长期需求，旧地图不废弃。

| 阶 | 获取难度定位 | 代表来源 |
| --- | --- | --- |
| 1-2 | 主世界地表随处可采（草、蕨、杜鹃叶等原版植物直接入药，现状保留） | 野外采集 |
| 3-4 | 主世界稀有生成的**灵药植物**（新增 worldgen，参考灵石矿的 placed_feature 模式） | 特定群系野生 + 灵田种植 |
| 5-6 | 下界/末地特产 + 灵田培育多代后的变异 | 跨维度 + 种植 |
| 7-8 | 妖兽掉落（妖丹、兽骨）+ 遗迹宝箱 | 战利品 |
| 9 | 唯一性奇物（龙血、仙芝），世界稀有结构限定 | 探索 |

### 1.2 灵药属性模型

每种灵药具备三项属性，通过**数据包**定义（`data/ninecun_lingtai/alchemy_herbs/*.json`，缺省的物品视为无属性普通药材）：

```json
{
  "item": "ninecun_lingtai:vermilion_lotus",
  "tier": 4,
  "element": "fire",
  "nature": "hot"
}
```

- `tier`：药材阶数（1-9）。
- `element`：五行/阴阳归属。丹方结算时新增**药性契合**微调：全部药材元素与丹方主属性"同或相生"时 envScore +0.03，出现相克药材时 −0.05（上限各一次）。这是鬼谷八荒"元素配平"的极简版——不标含量数值，只标归属，内容成本可控。
- `nature`：寒/热/平三性。寒性药要求曲线里文火占比更高、热性药武火占比更高——**数据包作者写火候曲线时的指导原则**，不参与运行时计算（避免双重惩罚）。

### 1.3 药龄（年份）

灵田产出与野生灵药带 NBT `HerbAge`（单位：游戏年，用现有寿元系统的历法口径）。药龄提供药力系数：`1.0 + min(药龄/百年, 0.5) × 0.2`，作用于该炉丹的 envScore（上限 +10%）。百年药材是玩家囤积和交易的硬通货，也给"时间"这个资源赋予炼丹价值。

### 1.4 灵田种植（新增方块体系）

- **灵田方块**：锄头右键灵土（灵石粉+泥土合成）生成，可种植 3 阶及以上灵药种子。
- **生长模型**：正常生长极慢（一茬 8 游戏日起）；玩家可对灵田**渡灵**（右键长按消耗灵力，机制复用打坐的灵力扣除）加速，元素契合的灵力加速更多——火属灵药用火灵力浇灌最优，联动灵根体系。
- **变异**：成熟时小概率（2% + 药龄加成）升 1 阶，是 5-6 阶药材的稳定但低速来源。
- **实现锚点**：参考原版 `CropBlock` + 现有 `SpiritualStoneUtility` 的灵气 NBT 读写。

### 1.5 妖丹入药

妖兽（现有 `CreatureCultivationData` 的修炼生物）被击杀时按其境界掉落**妖丹**（新物品，NBT 记境界与元素）。妖丹可作为 5 阶以上丹方的次药，且带来特殊效果：使用妖丹的丹，成功时品阶偏移额外 +1 的概率 15%，但丹毒 +50%（见 6.3）——"以妖入药，霸道而有隐患"，风味与风险并存。

## 二、器物层：丹炉与火源

### 2.1 丹炉五阶

现有丹炉更名为凡铁炉，成为最低阶。丹炉属性表：

| 丹炉 | 解锁期 | 炉温上限 | 保温率（heat 衰减/tick） | 容差加成* | 炉性 | 特性 |
| --- | --- | --- | --- | --- | --- | --- |
| 凡铁炉（现有） | 练气 | 600 | 1.0 | 0 | 无 | 现状 |
| 赤铜炉 | 筑基 | 700 | 0.9 | +2% | 火 | 武火段更持久 |
| 寒玉炉 | 金丹 | 700 | 0.75 | +4% | 水 | 文火段极稳 |
| 玄晶炉 | 化神 | 800 | 0.7 | +6% | 土 | 可炼 7 阶以下全部丹方 |
| 九龙神炉 | 大乘 | 900 | 0.6 | +10% | 混沌 | 唯一可炼 8-9 阶丹；结构方块搭建的多方块（复用现有炉体+部件块模式） |

\* 容差加成：判定火候命中时目标档位边界向外扩的百分比（600 制热度），直接降低操作难度。

**炉性相性**：丹炉炉性与丹方主属性相生时产量判定（完美时的产量 +1 概率）翻倍；相克时容差加成清零。混沌炉性视为与一切属性"平"，只吃自身容差。此为修仙模拟器"五行丹炉 2 倍产量"思路的收敛版。

**丹炉耐久**：每次炸炉扣 10% 耐久（成丹不扣），耐久低于 30% 时炸炉概率额外 +10%，耐久归零炉体碎裂掉落部分材料。用玉石/对应炉性材料右键**养炉**修复。防刷点：修复消耗随阶数上升。

### 2.2 火源四等

| 火源 | 解锁 | 点火方式 | 机制 |
| --- | --- | --- | --- |
| 凡火 | 练气 | 打火石（现状） | heat 一次性回满 600，自然衰减 |
| 灵火 | 筑基（学习后） | 空手蹲下右键炉，消耗灵力点燃 | 等效凡火，但点燃瞬间可指定落点热度（300/500 二选一），少一次等待或催火/收火的资源消耗；它是高效起手工具，不再是升档曲线的硬前置 |
| 地火 | 金丹 | 丹炉正下方 2 格内有熔岩源/灵魂火（下界天然满足） | **免点火，heat 恒定 450**（中火偏上），靠收火压到文火、催火推到武火、稳火守档——高阶批量炼丹的基础设施，但操作模型反转（从“防跌落”变成“主动增减”） |
| 三昧真火 | 化神（神通） | 施展神通点燃，持续消耗灵力 | 容差 +8%，且 fireScore 指数修正强制按九寸灵根计（4.4 节的手感惩罚豁免）——后期资质补偿手段 |

火源信息进入结算：地火炼制的丹成功率 +3%（火力稳定），三昧真火 +5%。

## 三、技艺层：丹道熟练度与丹师阶位

### 3.1 丹方熟练度（per-recipe，四段掌握模型）

**对齐现有功法掌握体系**（`TechniqueMasteryStage`：入门/小成/大成/圆满），丹方熟练度沿用同一套四段中文名与"积分达标升段"语义，让玩家在功法和丹道之间无需学习两套概念。积分增长：成丹 +1、废丹 +0.5、炸炉/化灰 +0.25（失败也是经验）。

| 掌握段 | 所需积分 | 效果 |
| --- | --- | --- |
| 入门 | 0（学会即入门） | 无 |
| 小成 | 20 | 火候容差 +1%；UI 明示该丹方的火候曲线阶段（无视神识信息模糊，"炼熟了闭眼都知道节奏"） |
| 大成 | 80 | 火候容差 +2.5% |
| 圆满 | 200 | 火候容差 +5%（与丹炉容差叠加）；解锁**自动炼丹**——投料点火后免操作，到时系统代为收丹（视为收在窗口中点，无早收/过火风险），按"该玩家该丹方历史平均 score − 0.05"直接结算。挂机产线免去了控火**和数火**两重操作，代价是只能产出"比你亲手炼稍差"的丹，手炼永远保有极品上限——"炼到圆满，闭着眼都知道什么时候开炉"，与无进度提示的设定自洽 |

存储：**不改动**现有 `PlayerLearnedAlchemyRecipeData` 的 StringList 结构（是否学会），熟练积分独立存新键 `ninecun_lingtai:alchemy_proficiency`（Compound：recipeId → double），实现模式照抄 `PlayerTechniqueProficiencyData`，零迁移成本。

### 3.2 丹师阶位（全局成长线）

按累计结算取阶位（自动授予，聊天广播+称号语言键）：

| 阶位 | 条件 | 全局加成 |
| --- | --- | --- |
| 一品丹师 | 累计成丹 10 炉 | 无（称号） |
| 三品丹师 | 成丹 60 炉且炼出过 3 阶丹 | 全丹方容差 +1% |
| 五品丹师 | 成丹 200 炉且炼出过 5 阶丹 | 容差 +2%，药渣产出率 +10% |
| 七品丹师 | 成丹 500 炉且炼出过 7 阶丹 | 容差 +3%，自动炼丹惩罚从 −0.05 减为 −0.03 |
| 九品丹圣 | 炼出过 9 阶丹 | 容差 +5%，每炉完美概率 +5% |

阶位只加"稳定性"，从不加品阶偏移——防止老玩家无脑碾压玩法。

### 4.2 AI 参悟（复用现有功法参悟链路）

现有 `TechniqueComprehensionService` 已打通"玩家写理解 → OpenAI/DeepSeek 评分"的链路。丹方参悟完全复用：

- 神话丹方（`content` 只写"以何为主药、文武火大概节奏"的叙述性丹方）学习时，玩家需**用自己的话写出对火候与药性的理解**（复用 `LearnTechniquePacket` 的 2000 字限制与校验）；
- AI 打分（0-100）决定：< 40 学习失败（可重试，每次消耗一枚人品灵石防刷——灵石为天/地/人三品，口径见 `docs/灵石.md`）；40-79 学会且初始熟练积分 = 分数 × 0.1；≥ 80 学会且初始熟练积分 20（直达小成）、首炉必不炸炉；
- 服务器未配置 AI Key 时回退为固定 60 分（保底可玩，呼应审计中 AI 配置为可选项的现状）。

## 五、玩法层扩展：按丹方复杂度渐进的分段投药

分段投药已经下沉为丹方的**可选工序能力**，不再与“六阶以上”硬绑定。仍复用现有 5 个输入槽和 1 个输出槽：

- 玩家空闲时先选择已学丹方；服务端验证学习状态、炼制境界和炉内已有材料。选方后，写入 `feed_plan` 的槽位保持为空并显示封印；
- `feed_plan` 每步指定槽位、火候阶段、阶段内开放起点、最佳投入点和书面窗口终点。到达开放点后只允许投入该槽对应的正确材料；
- 窗口起止边缘投药分约 0.70，最佳点 1.00；超过 `window_end` 但未跨阶段仍可补投，分数降至最低 0.25并失去完美资格；跨阶段仍未投直接进入漏药/药渣分支；
- 工序分 = 65% 火候 + 35% 投药，再沿用核心评分中原 35% 操作权重。未写 `feed_plan` 的丹方令工序分等于火候分，旧内容完全不漂移；
- 会话把选定丹方、已投/漏投/迟投掩码和投药分写入丹炉 NBT。关界面或断线不停止炼制；重开后只恢复“封/投/缺”等客观状态，不恢复客户端计时。

**复杂度阶梯**：聚气散保持五味开局一次投齐；草还丹在第二段延后投一味；玉髓丹结合一次升降温与第二段投药；结金丹分两段投两味。后续丹方按主题决定是否增加工序，而不是简单按阶数一刀切。高阶丹仍可拥有更多步骤，但第一版每个槽至多出现一次。

**与“无进度提示”原则的关系**：槽位开放是丹方写明的仪式事件，只同步位掩码，不同步阶段百分比、剩余时间或 `refiningTicks`。它是动作提示，不是进度条。

## 六、产出层：丹药十二类、丹毒与耐药

### 6.1 效果模型 v2（pill_effect → effects 数组）

现有 `pill_effect` 只有治疗。扩展为 `effects` 数组（保留旧字段解析，旧丹方视为单条 heal 效果）：

```json
"effects": [
  { "type": "heal", "max_health_fraction": 0.10, "flat_healing": 3.0 },
  { "type": "restore_spirit", "element": "root_elements", "amount": 50 },
  { "type": "spirit_infusion", "fraction_of_next_layer": 0.05 },
  { "type": "breakthrough_energy_discount", "discount": 0.15, "duration_ticks": 72000 },
  { "type": "proficiency_gain", "technique_proficiency": 15 },
  { "type": "lifespan_add", "years": 20 },
  { "type": "toxin_cleanse", "amount": 30 },
  { "type": "defense_repair", "fraction": 0.5 },
  { "type": "tribulation_resist", "damage_reduction": 0.2, "strikes": 3 },
  { "type": "revive_window", "duration_ticks": 200 },
  { "type": "root_length_add", "inches": 0.1, "lifetime_limit": 3 },
  { "type": "food", "nutrition": 20, "saturation": 12.0 }
]
```

**每个 type 的挂接口径（与现有代码一一对应，防止空中楼阁）**：

| type | 挂接现有系统 | 口径说明 |
| --- | --- | --- |
| heal | `AlchemyPillUtility`（现有） | 现状唯一效果，保留 |
| restore_spirit | `PlayerSpiritualEnergyData.addEnergy` | `element` 取 `root_elements`（按灵根元素均分）或指定元素 |
| spirit_infusion | `CultivationUtility.getRequiredSpiritualEnergy(下一层)` | 修为丹：按"下一层升层需求的百分比"注入灵根元素灵力。**项目中不存在独立的修为进度值，进度即灵力池**（`tryBreakthrough` 攒够即升），故修为丹本质是"浓缩打坐" |
| breakthrough_energy_discount | `PlayerCultivationManager.consumeEnergyForTarget` | 突破丹：服用后 N tick 内下一次突破的灵力需求打折。**现状突破没有成功率概念**（灵力足则必成），因此突破丹折抵"需求量"而非"成功率" |
| proficiency_gain | `PlayerTechniqueProficiencyData.setProficiency` | 悟道丹：为指定/当前修炼功法加熟练度。数值对齐功法四段口径（小成 60 / 大成 360 / 圆满 1800），一枚三阶悟道丹给 15-40 点属合理区间 |
| lifespan_add | `LifespanUtility` 年口径（1 年 = 36 游戏日 = 864000 tick） | 延寿丹：**仅练气~元婴有意义**——化神起 `isImmortal` 直接长生（代码现状），故延寿丹只规划在一至四阶，高阶不设 |
| toxin_cleanse | 本篇 6.3 丹毒 NBT | 清尘丹 |
| defense_repair | `PlayerDefenseResourceData` | 护体丹：修复防御资源，口径同打坐修复（`MEDITATION_DEFENSE_RESOURCE_REPAIR_PERCENT_PER_SECOND` 的一次性版本） |
| tribulation_resist | `TribulationManager` 伤害结算 | 渡劫丹：对天劫雷击的减伤 buff |
| revive_window | 结合防御资源/健康语义 | 济世丹：濒死保命窗口，实装依赖战斗健康体系审计问题（COMBAT-001）修复后再定细则 |
| root_length_add | `PlayerAptitudeData` 重写灵根（寸数 +0.1，夹在 1-9） | 洗髓丹：资质后天补救，一生限量计数写玩家 NBT |
| food | 原版 `FoodData` | 辟谷丹，趣味向 |
| soul_protection（预留） | 魂游/夺舍体系 | **魂魄星数是固定资质、项目无"神魂损伤"数值**，固魂类效果暂列预留接口，待魂游体系数值化后再填，不提前发明口径 |

所有数值先经 `AlchemyGrade.getEffectMultiplier()`（品阶每级 +5%，现有实现）缩放，再落地。每个 type 对应一个服务端 `PillEffectHandler`，注册表模式便于扩展。

### 6.3 丹毒（全局硬约束）

**没有代价约束的丹药体系必然通胀**。每次服丹累积丹毒（玩家 NBT `ninecun_lingtai:pill_toxin`）：

```
丹毒增量 = 丹方阶数 × 5 × (1.3 − 0.3 × 品阶rank/9) × 妖丹系数(1.5 或 1.0)
```

（同阶下，品阶越高丹毒越少——极品丹更"纯净"，又一个追高品的理由。）

| 丹毒值 | 状态 | 效果 |
| --- | --- | --- |
| 0-99 | 无恙 | 无 |
| 100-149 | 药蚀 | 打坐吸收效率 ×0.7，丹药效果 ×0.85 |
| 150-199 | 侵髓 | 上述加重（×0.5 / ×0.6），持续反胃粒子 |
| ≥ 200 | 毒发 | 拒绝服用任何丹药，每分钟扣 1 心，直至降到 200 以下 |

消解：自然每游戏日 −10；打坐时每分钟额外 −2；清尘丹类直接 −N。丹毒把"丹药当糖吃"变成"丹药是战略资源"，同时给解毒丹一个永久市场。

### 6.4 耐药性（按类别）

同一**类别**丹药在滚动窗口（3 游戏日）内重复生效递减：100% → 75% → 50% → 25%（下限）。窗口过后重置。修为丹额外硬规则：**每个小层内，丹药累计注入的灵力最多为该层升层需求（`getRequiredSpiritualEnergy`）的 30%**，玩家 NBT 按层计数、升层清零，剩余 70% 必须打坐——丹药辅修，不能代修，保护核心修炼循环。

## 七、天地层：丹劫与环境进阶

### 7.1 丹劫（七阶及以上）

结算判定为"成功且品阶偏移 ≥ +1"的 7 阶+丹会**引动丹劫**（天道不允许轻易出世的好丹）：

- 复用 `TribulationManager` 小型化：炉顶聚云，3 道雷（间隔 3 秒）劈向丹炉；
- 玩家须留在炉 8 格内**护丹**（长按火候条持续灌注灵力，每秒消耗 = 该丹维持成本 ×3）；
- 每道雷结算：灌注中 → 炉承伤（耐久 −5%）；未灌注/灵力断 → 30% 概率丹毁炉损（耐久 −30%）；
- 全部顶住：品阶额外 +1（可借此突破 7.3 节 rank 9 上限到"极品"标记，全服广播）。

丹劫让高阶炼丹的最后三十秒变成小型 boss 战，也是"庞大体系"在演出上的收束点。

### 7.2 聚灵与洞府（远期）

聚灵阵物品/结构提升局部灵气倍率（直接挂进 `ElementEnvironmentManager` 的规则叠乘），使"洞府丹房选址+建设"成为环境分的可建造来源。列为远期：环境体系当前由数据包驱动，先不引入动态规则源，避免与打坐/修炼共用倍率时的平衡连锁。

## 十二、平衡与反作弊备忘

1. **自动炼丹的产线上限**：自动结算按历史均值 −0.05 且不触发完美/丹劫，保证极品丹只出自手炼——挂机产量、手炼质量，两个赛道不互吃。
2. **修为丹 30% 硬顶**（6.4）：任何数值调整都不得突破，这是修炼核心循环的底线。
3. **丹毒不可交易转嫁**：丹毒挂玩家不挂物品，代吃小号再倒手无意义（丹药本身可交易，毒自己扛）。
4. **洗髓丹一生限量**：`lifetime_limit` 计数写玩家 NBT，死亡/夺舍均不重置（夺舍者继承目标肉身的已洗次数，联动占据体系的肉身语义）。
5. **服务端校验清单**：投料窗口时序、丹炉阶数 vs 丹方阶数、火源合法性（地火需真实检测下方熔岩）、AI 参悟重试计费——全部服务端二次校验，客户端 UI 状态仅作展示。
6. **经济回收**：丹炉养护、参悟重试、灵田渡灵三处灵石/灵力回收点，对冲丹药产出带来的资源通胀。
