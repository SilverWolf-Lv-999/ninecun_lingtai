## 二、火候曲线设计原则（先读这节再看配方）

点火一次 heat = 600，每 tick 自然 −1，因此**自然节奏**是固定的：

```
t ∈ [0, 200)    武火（heat 600→401）
t ∈ [200, 400)  中火（heat 400→201）
t ∈ [400, 600)  文火（heat 200→1）
t = 600         熄火（炼制中 = 化灰）
```

由此得出五条曲线设计原则，本册所有配方按此编排：

1. **教学丹顺应自然**：时长 500、曲线 `武 0.4 / 中 0.4 / 文 0.2` 的丹与自然衰减前 500 tick **逐段完全重合**，点一次火不做任何操作即满命中——这是练气期的"第一炉丹"体验（聚气散）。
2. **开炉时机是第一层深度**：玩家可以**点火后等温度落到目标档再按"开始炼制"**。开局要文火的丹（清尘丹），老手会等 400 tick 再起炉——不用任何新机制，玩家自己发现的技巧。
3. **时长 > 600 是第二层门槛**：一次点火撑不满全程，必然要续火（打火石，回满 600 会打断低火段）或**灵力维持**（锁温不衰减）。二阶起全部丹方时长 > 600，即"筑基期必须学会灵力控火"。
4. **低火尾段是维持教学**：`…/文 0.5` 结尾的长丹，尾段只能靠维持（续火会把温度打回武火），这是灵力消耗的主要出口。
5. **无进度提示，收丹靠数火**（核心篇设计原则第 6 条）：`refiningTicks` 不同步客户端，没有进度条。玩家点"收丹"时按 `t = 已炼时长 / 成丹时长` 分支：`t<0.8` 炸炉、`0.8≤t<1.0` 废丹、`[1.0,1.3]` 成丹窗口、`(1.3,1.6]` 过火每超 0.15 品阶 −1、`>1.6` 焦丹化灰。时长编排服从"可数火"：**一阶统一 ≤ 500**——一次点火有 600 tick 火，`t=1.0` 落在火熄之前，"点火即起炉、火快熄时收丹"自然落进窗口，第一炉丹不需要计时技巧（若用 600 则 `t=1.0` 与 heat 归零重合，窗口被化灰吃掉）；**二阶起按 600 的整数/半整数倍编排**，一次点火 30 秒就是沙漏，"三次火收丹"必须是可数的。丹香（`t=1.0` 触发，经魂魄星数过滤：5-7 星必闻、3-4 星 80% 且可迟至 5%、1-2 星 40%）是唯一软信号。窗口宽度 0.3 × 时长 = 一阶丹 7.5 秒容错、三阶凝神丹 30 秒容错——时长越长绝对容错越宽，抵消长丹计数误差的累积，这是"难而不苛"的关键。
6. **复杂度渐进，不按阶数硬切**：凡火拉满仍是粗调；已实装的催火/收火/稳火允许连续精调。聚气散只教自然衰减，草还丹增加一次延后投药，玉髓丹增加一次升温—投药—降温，结金丹增加两次阶段投药。后续丹方按操作主题逐项叠加，避免新手第一炉同时面对全部机制。

## 四、数值推演验证（三个画像的完整算例）

> 公式回顾（核心篇第七节）：无分段投药时 `operation=fire`；有 `feed_plan` 时 `operation=fire×0.65+feed×0.35`。随后 `score = operation×0.35 + env×0.20 + root×0.15 + soul×0.15 + realm×0.15`；`成功率 = clamp(baseSuccess(tier) × score, 0.05, 0.98)`。

> 三个画像共用的收丹前提：无进度提示，玩家按"数火/看火/闻香"自行收丹。算例默认收在窗口内（一阶丹"火快熄时收"天然落窗，见曲线原则 5）；收偏的惩罚是独立分支，不进公式。

### 画像 A：练气五层新手，"点一次火就不管了"

**第一炉：聚气散**（木属，曲线 武0.4/中0.4/文0.2，时长 500）。三寸单木根、3 星魂魄、平原白天（木 ×1.1）、凡铁炉。点火后立即起炉、全程不操作、火快熄时（约 550 tick，t=1.1）收丹：

- **fireScore**：曲线与自然衰减逐段重合——武 [0,200) √、中 [200,400) √、文 [400,500) √、养丹段 [500,550) 目标文实际文 √。命中 550/550 = 1.0；灵根手感指数 1.6−0.6×(3/9) = 1.4 → fireScore = **1.0**
- **envScore** = 1.0 + 0.10×(1.1−1) = **1.01**；**rootScore**（SAME）= 1.0×(0.6+0.4×0.333) = **0.733**；**soulScore** = 0.55+0.45×(3/7) = **0.743**；**realmScore**（Δ=0，5 层）= 0.85+0.15×5/9 = **0.933**
- **score** = 1.0×0.35 + 1.01×0.20 + 0.733×0.15 + 0.743×0.15 + 0.933×0.15 = **0.913**
- **成功率** = 0.95 × 0.913 ≈ **87%**；品阶偏移：0.913 ∈ [0.90, 1.00) → **+1**，出一阶二品

教学丹的确定性甜头：第一炉丹八成七能成、还超一品——"我能炼丹"的正反馈拉满（一阶二品效果倍率也只比一品高 5%，不破坏平衡）。

**同一个人直接上草还丹**（中0.4/文0.6，500）而不学技巧——立即起炉全程不管、550 收丹：目标中火段 [0,200) 实际武火 ✗，文火段 [200,500) 里 [200,400) 实际中火 ✗、仅 [400,500) √，养丹段 √。命中 150/550 = 0.273 → fireScore = 0.273^1.4 ≈ **0.163** → score = 0.057+0.202+0.110+0.111+0.140 = **0.620** → 成功率 ≈ **59%**，品阶 −1。

结论：教学丹"无脑"高成功，但**换一张曲线不匹配自然衰减的丹方，同样的无脑打法立刻掉到六成**——难度差写在丹方曲线里，不是写在数值墙上。

### 画像 B：同一个新手学会了"延迟起炉 + 尾段维持"

草还丹同上，但点火后等 200 tick 再起炉（中火开局命中）、火将熄时长按锁温撑完文火段、窗口内收丹——命中约 95%：

- fireScore = 0.95^1.4 ≈ 0.931 → score = 0.326+0.202+0.110+0.111+0.140 = **0.889** → 成功率 ≈ **84%**，品阶偏移 0（稳定出一阶一品）

结论：同一个玩家、同一张丹方，学会两个技巧成功率从 59% 提到 84%——**+25 个百分点的操作收益，显著且免费**，这是难度曲线的核心正反馈。

### 画像 C：金丹三层老手在恶地炼凝金丹（跨系统联动验证）

凝金丹（金属，tier 3，base 0.85）。九寸单金根、7 星、恶地白天（金 ×1.5）、**寒玉炉**（炉性水，金生水=相生 → 容差 +4% 生效；若误用赤铜炉，火克金 → 容差清零，这是器物层的选择深度）。认真控火命中 95%：

- fireScore = 0.95^1.0 = **0.95**；envScore = 1.05；rootScore = 1.0；soulScore = 1.0；realmScore（Δ=0，3 层）= 0.9
- **score** = 0.3325+0.21+0.15+0.15+0.135 = **0.978** → 成功率 = 0.85×0.978 ≈ **83%**；品阶偏移：0.978 ∈ [0.90, 1.00) → **+1**（三阶三品丹方出三阶四品）
- 完美线（score ≥ 1.0 且命中 ≥ 0.9）差 realmScore：需练到金丹八九层（realmScore → 0.98-1.0）才够——**同阶完美 = 接近满层**，给"境界内成长"持续意义
- 环境速度：1800 / min(1.5, 1.5) = 1200 tick，恶地选址省 30 秒。**收丹计时也要跟着环境换算**：1200 tick = 整两次点火，"第二次火将熄时收丹"——环境角标上的倍率就是玩家心算的依据，算错了按原时长等到 1800 tick，t=1.5 已入过火区（品阶 −1 起步）

结论：顶配老手炼同阶天花板丹约 83% 成功 + 稳定超品，17% 失败大部分出药渣——高阶炼丹始终有心跳，但期望收益为正。

### 平衡结论

三个算例横向对比：教学丹无脑 87% → 同打法换丹方 59% → 学技巧 84% → 顶配老手 83%(+1 品)，操作、资质、境界、选址、器物五个变量各自贡献可感知、可叙述的差异，且没有任何单变量能一票否决（除环境倍率 = 0 的禁炉线）——**"符合"体现在每个数字都能向玩家解释来源**。收丹时机不进公式，它是所有画像共同面对的"手上功夫"：数火、看火、闻香，错了自负。

### 5.3 结算时序（服务端，一次炼制的完整流程）

1. 空闲时先由 `SelectAlchemyRecipePacket` 选择已学丹方；服务端据 `feed_plan` 封印延后槽。旧丹方未选时仍可按完整材料自动匹配；
2. `startRefining`：验证开局槽齐全、延后槽为空，记录炼丹人、清零命中/投药分并锁定 `activeRecipeId`；**`refiningTicks` 保持服务端私有**；
3. `serverTick` 每 tick：先执行催火/收火/稳火并扣灵力，再统计目标火候命中；按服务端阶段更新 open/missed 掩码；
4. 延后槽收到正确材料时按阶段内位置计分；窗口后同阶段补投记迟投，跨阶段未投记漏投；
5. `refiningTicks` 到实际成丹时长时按魂魄星数处理丹香；除丹香与客观槽位事件外不发进度信号；
6. 玩家收丹：先按时机分支；漏投/材料篡改固定药渣；否则以工序分参与成功率、品阶和加产结算；
7. 无论结果均清空活动会话；保留选定丹方，便于下一炉重复装药。

### 5.4 实装注意点（含审计衔接）

1. **灵石品级匹配**：v2 ingredient 增加可选 `"grade": "human|earth|heaven"`，匹配 `SpiritualStoneUtility` 的品级 NBT；未写 grade 则任意品级可用（筑基丹人品即可，避免新手卡天品）。
2. **药龄计时用 `level.getGameTime()`**，不用 `overworld().getDayTime()`——审计已发现寿元系统用 dayTime 受 `/time set` 影响（LIFE 组 finding），药龄不重蹈覆辙；年换算沿用 `LifespanUtility.TICKS_PER_YEAR`。
3. **每 tick 同步问题**：~~现有 `serverTick` 每 tick `setChangedAndSynchronize`（审计 ALCH 组性能项）~~ **已修（2026-08-12）**：`serverTick` 改为每 tick 只 `setChanged()`，区块级广播降为每 20 tick 一次（菜单内温度仍走 `ContainerData` 每 tick 平滑）。实装火候系统时沿用此模式，命中计数只存服务端不同步。
4. **部件块双掉落**（审计 ALCH 组）：M1 动 `AlchemyFurnaceBlockEntity` 时一并修 `AlchemyFurnacePartBlock.onRemove` 与主块互删的重复掉落。
5. **`quartz` / `scute` 命名**：1.20.1 下石英物品 ID 为 `minecraft:quartz`、鳞甲为 `minecraft:scute`（1.20.5 后才改 `turtle_scute`），实装照本册 ID 即可。
6. **模拟命令**：M1 一并交付 `/ninecun alchemy simulate <recipe> <count> [profile]`（OP 权限），按画像参数批量掷骰输出成功率/品阶分布——平衡回归的基础设施，本册第四节的算例就是它的验收用例。
7. **无进度提示是硬约束**：`refiningTicks`、命中计数、fireScore 一律不进 ContainerData、不进 `getUpdateTag`/`handleUpdateTag`、不进任何 S2C 包（丹香 toast 除外）。~~`setChangedAndSynchronize` 走的 `getUpdateTag` 把整个 `saveAdditional` 的 NBT 原样下发，`refiningTicks` 是漏的~~ **已修（2026-08-12）**：`getUpdateTag` 已拆分为最小同步集（items + refining + heat），`RefiningTicks`/`ActiveRecipe` 保持服务端私有——改装客户端也读不到进度。后续实装新增字段时沿用该拆分，勿改回 `saveWithoutMetadata()`。
8. **升降温现由三式控火承接**：文→中用催火，中/武→文用收火，稳火负责守档；灵火未来上线后只优化起手效率，不再作为曲线可炼性的硬依赖。

### 7.2 三组结金丹工序画像

同一资质/环境下只改变火候与投药精度：

| 画像 | 火候 | 投药 | 工序分 | 理论成功率 | 本次 5000 次成丹 |

### 7.3 客户端人工闭环验收单

1. 选草还丹，只装四味开局材料，确认花叶槽封印且可起炉；
2. 起炉后关闭并重开界面，确认炼制继续、选方和槽位状态恢复、目标火候显示“？”；
3. 长按催火回中档，进入第二段后花叶槽金光开放；投入花叶，再长按稳火并在丹香后收丹；
4. 分别在最佳点、`window_end` 后同阶段、下一阶段后尝试投入，验证精准、迟投降品/无加产、漏投药渣；
5. 控火时关界面、离炉、死亡或清空灵力，确认服务端立即释放并在灵力不足时提示；
6. 用未学丹方、越界位置、炼制中换方、错误物品和非法控火枚举验证服务端拒绝。
