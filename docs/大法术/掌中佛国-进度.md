# 掌中佛国开发进度

已按“分步骤”推进，目前完成了动态佛国、成员生命周期闭环、成员摘要分页、迁移边界收紧、真实维度传送过渡、水墨覆盖层初版、单成员释放手势，以及释放结果反馈；仍按小步实现后续实体能力，不一次性堆叠完整多选 UI。

## 第一阶段：动态佛国维度基础层（已完成）

1. 新增佛国独立持久化状态：
    - `common/spell/palm_buddha/PalmBuddhaRealmState.java`
    - 保存施法者 UUID、佛国维度 ID、佛国随机种子、佛国名称、创建时间。
2. 新增佛国维度管理门面：
    - `common/spell/palm_buddha/PalmBuddhaRealmManager.java`
    - 每个玩家唯一佛国；按需创建、注册、加载；复用 `ThreeThousandRealmManager` 动态维度 API。
3. 扩展现有动态维度 API：
    - `registerManagedRealmDefinition`
    - `getOrLoadManagedRealm`
    - `isManagedRealm`
    - 动态维度卸载、存档注册表过滤同时覆盖佛国维度。
4. 使用 Mixin 接入服务器生命周期：
    - `MinecraftServerPalmBuddhaRealmMixin`
    - `DimensionArgumentRealmAccessMixin`
    - `PlayerListRealmLoadMixin`
    - `MinecraftServerRealmLoaderMixin`
    - `MinecraftServerRealmSaveMixin`
    - 不新增佛国专用 Forge 事件处理器。

## 第二阶段：准心单选与成员生命周期（已完成）

1. 注册法术：
    - `ninecun_lingtai:palm_buddha`
    - 功法数据：八品、utility、基础消耗 32、练气一层起步、最低参悟分 88。
2. 实现准心单选在线玩家：
    - 客户端只发送锁定目标 UUID。
    - 服务端重新解析玩家并验证存活、同维度、距离不超过 32 格、视线和动态维度限制。
    - 不信任客户端位置或境界数据。
3. 实现境界限制：
    - 练气期最多影响筑基目标。
    - 其他境界只能影响同境界或低境界目标。
    - 当前无修为目标按可影响处理，境界缺失的施法者不能施法。
4. 实现玩家成员持久化：
    - `palm_buddha_members.json`
    - 保存成员 UUID、施法者 UUID、进入前维度、坐标和视角。
    - 修正删除失败时的内存回滚，避免持久化失败造成状态漂移。
5. 实现真实维度迁移：
    - 使用 `ServerPlayer.changeDimension(...)` 和现有动态维度传送器。
    - 不创建假页面，不烘焙其他玩家摄像机视角。
6. 实现成员生命周期闭环：
    - 玩家登录后通过 `PlayerListRealmLoadMixin` 恢复到施法者佛国。
    - 玩家死亡重生后通过同一 Mixin 恢复到施法者佛国。
    - 成员不能通过普通维度迁移绕出佛国；只有服务端授权释放流程允许离开。
    - 施法者只能释放自己佛国中的在线成员，目标归属由服务端校验。
7. 预留后续 UI 所需查询接口：
    - 按施法者查询成员。
    - 查询成员归属和对应佛国维度。
    - 判断成员是否处于预期佛国。
8. 新增服务端释放包：
    - `ReleasePalmBuddhaMemberPacket`
    - 只携带目标 UUID，不携带位置；服务端负责归属校验与原位置恢复。

## 第三阶段：成员摘要与按需分页协议（已完成）

1. 新增轻量成员摘要：
    - `PalmBuddhaMemberSnapshot`
    - 包含 UUID、名称、在线状态、当前维度、是否仍在预期佛国、当前位置摘要和可选境界。
    - 所有字段均由服务端生成；不发送区块、实体副本或其他玩家摄像机数据。
2. 新增有界分页数据：
    - `PalmBuddhaMemberPageSnapshot`
    - 每页最多 12 名成员，总页数和总成员数都有协议硬上限。
    - 服务端按 UUID 稳定排序后分页，避免离线名称变化造成页漂移。
3. 新增按需请求/同步包：
    - `RequestPalmBuddhaMembersPacket`
    - `SyncPalmBuddhaMembersPacket`
    - 请求只接受页码；响应只发送给请求对应的施法者，服务端不会把佛国成员列表广播给其他玩家。
4. 新增客户端摘要缓存：
    - `ClientPalmBuddhaMemberManager`
    - 只缓存服务端返回的一页摘要，为后续水墨 UI 提供数据源。
    - 暂不创建 Screen、第二摄像机或烘焙视角页面。

## 第四阶段：状态一致性和迁移边界（已完成）

1. 动态维度恢复改为“先查已加载世界，再按需加载托管动态维度”：
    - 释放成员和异常恢复流程不再因原维度未加载而直接误回退主世界。
    - 复用 `ThreeThousandRealmManager.isManagedRealm(...)` 与 `getOrLoadManagedRealm(...)`。
    - 对持久化佛国定义增加生命周期异常时的延迟解析兜底。
2. 迁移失败保持事务一致性：
    - 收入佛国失败会删除刚写入的成员记录。
    - 释放或异常恢复失败会恢复成员记录，避免玩家已经被拦截在佛国外却仍被错误标记为成员，或反之。
3. 异常恢复策略明确化：
    - 施法者佛国定义缺失时尝试恢复成员保存的原始世界。
    - 原始维度不存在、动态维度无法加载或安全位置不可用时，回退主世界安全出生点并记录日志。
4. 网络包生命周期完善：
    - `SyncPalmBuddhaMembersPacket` 在客户端工作排队后正确标记为已处理。
    - 客户端成员摘要仍仅在断开连接 Mixin 中清理，不新增 Forge 事件链。
5. 本阶段继续遵守真实维度渲染原则：不创建假页面、不烘焙其他玩家摄像机、不发送区块或实体副本。

## 第五阶段：真实维度传送过渡与不可交互状态（已完成）

1. 通过客户端 Mixin 监听真实 `ClientboundRespawnPacket`，只对当前本地玩家的真实渲染目标做白化、墨晕和失声过渡。
2. 不创建第二摄像机、离屏世界、实体副本或其他玩家视角页面。
3. 传送期间通过 `MinecraftMixin`、`MouseHandlerMixin`、`KeyboardInputMixin` 和 `SoundEngineMixin` 收紧输入与声音。
4. 服务端仍以真实 `ServerPlayer.changeDimension(...)` 结果为准，客户端超时自动清理。

## 第六阶段：成员水墨覆盖层初版（已完成）

1. 新增无 `Screen` 的 HUD 覆盖层，由单个 Shader 绘制宣纸、墨色边框、印章、行分隔线和动态墨迹。
2. 客户端只请求并缓存当前成员摘要页，不发送区块、实体副本或其他玩家摄像机数据。
3. 当前支持左右翻页；背包键会被消费但不会打开原版背包，Esc 通过 `KeyboardHandlerMixin` 收卷覆盖层。
4. 选中态、分页状态和真实摄像机渲染均不依赖第二摄像机或离屏页面。

## 第七阶段：单一几何区域选择（已完成）

1. 新增共享几何布局工具，面板尺寸、行区域和 Shader 行高使用同一套计算。
2. `MouseHandlerMixin` 捕获覆盖层左键，在成员行几何区域内只选择一个成员索引。
3. 选中索引通过 `SelectedRow` uniform 传给 Shader，选中行由墨色/金色晕染表现，不创建按钮集合或原版 `Screen`。
4. 鼠标输入仍只作用于当前真实玩家画面，未创建其他玩家视角或实体副本。

## 第八阶段：单个成员释放手势（已完成）

1. 复用已有成员行几何区域：左键选中成员后，在同一行右键触发释放，不新增按钮集合、不创建原版 `Screen`。
2. 客户端释放包只发送目标 UUID；不发送位置、维度、境界或摄像机数据。
3. 服务端再次校验成员归属、在线状态、目标是否仍在预期佛国，并由现有事务化传送流程恢复成员原始维度与坐标。
4. 释放状态提示只增加一条 Shader uniform：可释放行显示克制的朱砂边缘晕染；未创建第二摄像机、离屏世界、实体副本或假页面。
5. 发送释放请求后按原页码重新请求成员摘要，仍由服务端返回最终真实状态。

## 第九阶段：释放结果反馈与确认状态（已完成）

1. 新增 `PalmBuddhaReleaseResult`，服务端将成功、失败及有限失败原因统一为轻量结果；失败原因不携带位置、维度或实体数据。
2. 新增 `SyncPalmBuddhaReleaseResultPacket`，结果只发送给发起释放请求的施法者。
3. 释放请求进入等待状态；客户端不在发送请求后提前刷新摘要，避免短暂显示过期成员状态；超过 80 tick 未收到回执时显示超时反馈。
4. 现有 Shader 覆盖层新增等待边缘、成功/失败印章晕染和短暂墨迹反馈；没有新增按钮、原版 `Screen`、第二摄像机、离屏世界或实体副本。
5. 结果反馈结束后才按当前页重新请求成员摘要，服务端摘要继续作为唯一真相。
6. 传送事务失败会返回明确的失败原因，并恢复成员记录；所有迁移和所有权校验仍在服务端完成。

## 下一阶段计划

第十阶段先实现“准心单选普通生物实体进入佛国”，仍不引入范围扫描、多选或批量迁移：

1. 复用现有准心目标边界校验，但服务端只接受可持久化、可安全迁移的 `LivingEntity`。
2. 为非玩家成员增加独立持久化记录，保存实体类型、原维度、位置、视角和必要的最小状态；不复制实体到客户端。
3. 复用真实维度迁移、登录/重载恢复和授权释放原则；失败时保持事务一致性。
4. 继续使用水墨 Shader 覆盖层反馈状态，不创建大量按钮或 Minecraft 原版 UI。
