# 设计
何为三千界？
1. 十个小世界(不算下界和末地)
2. 命名方式随机，但必须是这样的命名法：七星界、幽冥界、混沌界
3. 没有传送门可以前往，指令无法也无法前往
4. 地形生成和主世界完全一样，但不能和主世界共用一个种子

- - - 

# 实现思路
1. 使用动态数据生成。主世界算“人间界”，其它都随机中文命名，但不能是一堆乱码名字，比如什么(“人啊界”“啊欸界”)。因此，可以使用本项目提供的AI接口
2. 玩家第一次进入世界/重生(重生需要的配置项来决定)时，都是在随机的界域的随机坐标
3. 玩家进入一个界域时，使用本项目提供的通知系统，来告诉玩家这是什么界域，持续3s。
4. 内存卸载。mc在有维度时，也会一直保持加载，这会消耗大量内存，所以需要制作内存卸载，在维度没有玩家时，不要更新这个维度

# 问题？
1. 末地、地狱或别的mod的其它维度，咋办？解决方案：使用Json持久化保存玩家数据，等玩家从那些维度回去时，通过读取Json里存储的值，将玩家给送回原来的地方
2. 别的mod的自定义维度的传送门可能无法在本地开启咋办？解决方案：让结构认为就是在主世界
3. 有些自定义结构或许无法生成咋办？解决方案：修改维度数据中的有关维度判断的地方，让它以为是主世界就行
4. 注册ID是什么？注册ID为 "ninecun_lingtai:<维度的名称拼音+一串UUID>"，并创建一个新的Json文件表来管理各个注册ID与名称的对应关系
